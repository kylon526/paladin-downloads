Release status

The fully renamed Paladin candidate has not been published here yet. It creates a separate, empty installation and does not import previous rules or protector credentials. Earlier releases remain archived with their original filenames and signed bundle contents and require an existing configured installation. Follow the instructions for the version you download. Remove previous protection through its own controls before configuring Paladin on the same connection.

Opening a Paladin candidate for the first time

  1. Open the DMG and drag Paladin.app to Applications.
  2. Try opening it. If macOS says Apple could not verify the app, click Done.
  3. Go to System Settings → Privacy & Security → Security and click Open Anyway for Paladin. Confirm Open and authenticate if asked.

This approves Paladin specifically. The DMG does not remove the warning: this build is not Apple-notarized. Apple’s instructions.

Before you install

The DMG opens a custom drag-to-Applications window with just two icons. The app contains its monitor, CLI, gateway, and Python runtime, so there are no loose support files to copy. It does not include your rules, protector key, certificates, or network settings.

Candidate software is bundled inside Paladin.app. Dragging it copies the app, monitor, CLI, gateway, and runtime together; it does not configure protection. Opening the installed candidate starts its independent menu monitor; protection requires first-run setup. The app is locally signed and is not Apple-notarized. Coordinated installation, automatic updates, and automatic repair are not included yet. The DMG shows just Paladin and Applications; drag the app icon to copy all bundled software.
